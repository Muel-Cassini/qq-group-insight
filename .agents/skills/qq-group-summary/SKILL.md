# QQ 群聊消息汇总

把聊天记录导出变成「可读、可筛、可按天追溯」的汇总材料。**本技能只读输入、只在自己的输出目录里写文件，不联网、不调用外部命令。**

> 面向人的操作手册在 `GUIDE.md`（参数表、输出说明、故障对照、调参经验）；可调规则在 `config.json`（分类关键词、P0/P1 正则、展示长度），脚本每次运行自动读取，无需改代码。

## 一、前置：拿到导出

数据来源是用户本机的 [qq-chat-exporter](https://github.com/shuakami/qq-chat-exporter)（QCE，Rust/GPL-3.0，纯本地解析，不上传任何数据）：

1. 用户在 QCE 里选择目标群 → 导出为 **JSON**（长记录建议 JSONL）；
2. **务必勾选“同时下载图片/文件/表情”**，否则媒体清单只能登记引用名、无法真正查看内容；
3. 记下导出目录，以及媒体文件所在根目录（通常导出目录本身）。

导出完成后不要自己去猜字段结构：先跑一次脚本，看 `_report.md` 里的「丢弃记录数 / 缺时间戳 / 缺发送人」是否为 0；不为 0 再去读原始 JSON 的前几条核对字段名。

## 二、执行汇总

```powershell
python .agents/skills/qq-group-summary/scripts/qq_group_digest.py `
  --src  "<导出目录>" `
  --out  "artifacts/qq\<群名>-<日期区间>" `
  --media-root "<导出目录>" --media-check
```

常用参数：

| 参数 | 用途 |
|---|---|
| `--chat "子串"` | 只处理名称/ID 含该子串的会话（多群导出时必用） |
| `--from 2026-09-01 --to 2026-09-10` | 限定日期区间 |
| `--media-root <dir> --media-check` | 在指定根目录下真实探测媒体文件是否存在（不传则只登记引用，显示“未校验”） |

输出：

```
normalized.jsonl      归一化消息（每行一条，字段稳定，供后续比对使用）
digest/YYYY-MM-DD.md  每日汇总：P0/P1 聚焦区 + 主题分类 + 类内时间倒序
p1-todo.md            跨天 P0/P1 清单（谁、哪个群、什么时候、什么事）
media-index.md        文件/图片/视频清单（时间、群、发送人、消息摘要、路径、存在与否）
_report.md            解析统计与告警（输入文件、消息数、覆盖日期、异常计数）
```

## 三、分类与重要度口径（用户已确认）

**主题分类**（规则顺序即优先级，命中即归类；无命中为「闲聊」）：
公告通知 → 提问求助 → 资源分享 → 技术讨论 → 广告灌水 → 闲聊。
含图片/文件的资源类消息会加权到「资源分享」。

**重要度**：

| 级别 | 含义 | 触发规则（脚本内可改 `P0_PATTERNS` / `P1_PATTERNS`） |
|---|---|---|
| P0 | 决策/通知，必须知道 | `@全体成员`、`@all`、重要通知、紧急、务必、截止时间 |
| P1 | 需要你行动 | `@我`、待办、记得、麻烦、帮我看、求助、确认一下、疑问句（请问/为什么/怎么办/含 `？`） |
| P2 | 有价值信息 | 公告/资源/技术类、含文件或图片、转发合并记录 |
| P3 | 闲聊/噪音 | 其余；广告灌水一律降级为 P3 |

**时间维度**：按自然日切分（时区固定 UTC+8），每类内部按时间倒序；跨天的 P0/P1 另外汇总进 `p1-todo.md`。

## 四、汇总的写作要求（Agent 环节）

脚本只产出**材料**，最终「汇总」由你基于材料撰写：

0. **图片需要视觉模型**：`media-index.md` 里「存在=✅」的图片要靠图片读取能力查看。若当前模型不支持图片输入
   （`read_image` 会直接报错），必须明确告知用户「图片内容未读取」，并给出两个选项：切换到支持视觉的模型再跑，
   或由用户自行查看图片；**不要**凭文件名或尺寸编造图片内容。
1. **先读** `digest/*.md` 全部 + `media-index.md`；必要时读 `normalized.jsonl` 补上下文。
2. **真的看图片**：`media-index.md` 中“存在=✅”的图片，用图片读取能力逐个查看内容，并把视觉信息写进摘要（是报错截图、流程图、还是表情包要区分开）。不要只复述文件名。
3. **文件不要假装读过**：能直接读的（txt/md/csv/json/代码）读内容摘要；pdf/xlsx/zip 等无法解析的，明确标注「未解析」并说明可获得什么信息，绝不编造内容。
4. **话题串联**：同一话题跨天出现时合并叙述（谁先问、谁给了方案、后来是否解决），而不是逐条罗列。
5. **输出结构**：① 一句话结论 ② P0/P1 待办表（含来源消息时间）③ 按主题的实质内容总结 ④ 群内资源与文件清单 ⑤ 未解决问题/待跟进 ⑥ 噪音统计（广告、闲聊条数）。
6. 引用具体消息时保留「日期 时间 + 发送人」，便于回溯。敏感内容（手机号、身份证、私聊截图）默认脱敏。

## 五、红线

- 未经用户许可，不把群聊内容写入工作区以外的路径、不发送到任何外部服务。
- 只处理用户明确指定、且其本人有权处理的聊天记录。
- 不修改、不移动、不删除用户的原始导出文件。
